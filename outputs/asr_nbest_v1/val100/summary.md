# PhoASR N-best diagnostic — 100 new validation samples

## Selection and generation

- Cohort: first 100 IDs in the fixed validation ID order after excluding the previously evaluated hard-30 IDs; no outcome-based selection.
- Five candidates per sample: production greedy, beam width 3/5, and temperature sampling at 0.2/0.35.
- 500 candidate rows; duplicate candidate rate 61%; empty transcripts 0; generation failures 0.
- N-best generation took 1,008 seconds on the local RTX 4050. Confidence fields remain null because PhoASR does not expose reliable scores.

Oracle WER improved 29/100 samples, stayed equal on 71, and worsened none. Absolute WER gain was 0.0273 (7.5% relative); absolute CER gain was 0.0213.

This calculation gives 25/100 hash matches for current 1-best and 26/100 for WER oracle; among those, 15 samples in each mode had zero matched calls. Paired proxy outcomes versus current 1-best: WER oracle improved 2 samples, worsened 2, tied 96; consensus improved 1, worsened 2, tied 97. Aggregate WER-oracle gains were small: tool F1 +0.0014, state +0.0100, proxy +0.0103. Consensus did not improve tool F1, though state match was +0.0100 and proxy +0.0078.

Downstream oracle was not run because scoring each candidate requires multiple ToolEnv trajectories for the same sample, conflicting with the competition's exactly-one-ToolEnv requirement. Each completed mode used one ToolEnv per sample.

## Conclusion

On this larger, non-hard-selected cohort, the PhoASR search space more often contains a lower-WER transcript than the production greedy choice, but the practical downstream gain remains modest. WER-oracle selection has only a tiny call-F1 lift; consensus is essentially tied on proxy. This supports continuing to prioritize Qwen action policy over ASR reranking. No production or submission behavior changed.
